This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a static personal portfolio / CV site for Anthony Ha-Anh Pham, hosted via GitHub Pages at the domain in `CNAME` (anthonyhpham.me). No bundler or package manager is used — the site is plain HTML and CSS with no JavaScript. The only build step is regenerating `tailwind.css` (below), which is committed so GitHub Pages serves it as-is.

## Development

To preview locally, open `index.html` directly in a browser or serve it with any static file server:

```
python -m http.server
```

### Rebuilding Tailwind

`tailwind.css` is generated by the Tailwind **v3.4.17** standalone CLI from `tailwind.input.css`, using `tailwind.config.js` (which scans `index.html` for class names and maps the theme colors to CSS variables). **Rebuild it whenever a Tailwind class is added to `index.html` that isn't already used** — otherwise that class has no CSS. Never hand-edit `tailwind.css`; custom styles go in `styles.css`.

```
./.tools/tailwindcss-linux-x64 -c tailwind.config.js -i tailwind.input.css -o tailwind.css --minify
# add --watch while editing to rebuild on save
```

The binary lives in the git-ignored `.tools/` directory. To get it on a new machine, download the asset for your platform from https://github.com/tailwindlabs/tailwindcss/releases/tag/v3.4.17 (e.g. `tailwindcss-linux-x64`), check it against that release's `sha256sums.txt`, and `chmod +x` it. Stay on v3.4.17 unless deliberately upgrading — v4 changes the config format and preflight.

There are no tests, no linting configs, and no CI pipelines.

## Architecture

The entire site is a single page in `index.html`: a sticky `<nav>`, four stacked `<section>` elements, and a `<footer>`. The nav name shows in full from `sm` (640px), as "Anthony Pham" below that, and is hidden below 360px so the bar never wraps (the h1 still shows the name). Test layouts at 320px — it's the WCAG reflow width.

1. **Intro** — profile photo, name, social icon links, a short bio, and a tech stack grid of logo tiles (`.tech-grid` / `.tech-card`, each tile links to the tool's homepage). Below `sm` the tiles become compact rows (small logo beside label, `flex … sm:block`); from `sm` up they're stacked logo-over-label tiles
2. **Projects** (`#projects`) — card grid; each `.project-card` is a flex column whose `.project-header` grows so the tag row (`.project-footer`) sits at the bottom
3. **Research** (`#research`) — full-width `.research-feature-card`s in a two-column layout (`md:w-1/3` metadata + `md:w-2/3` overview and contributions)
4. **Teaching** (`#teaching`) — a grid of `.teaching-card`s, followed by a "YouTube Series" grid of `.youtube-card`s with playlist thumbnails

**Styling** splits between:
- `styles.css` — color tokens, base font/background, the global `:focus-visible` ring, skip link, sticky nav, link styles (`.accent-link`, `.ext-link`), the shared card base, the responsive `.tech-grid`, the single `.tag` pill style, and YouTube thumbnail sizing
- `tailwind.css` (generated, see above; linked before `styles.css`) — Tailwind utilities for layout, spacing, typography, and responsive breakpoints throughout `index.html`

**Colors are tokens.** Every color is a CSS variable in the `:root` block at the top of `styles.css` (`--bg`, `--text-strong` / `--text-body` / `--text-muted`, `--accent` / `--accent-light`, white-overlay surfaces and borders, and `color-mix()` tints derived from the accent). Never write a raw hex/rgba value elsewhere — add or reuse a token. In `index.html`, text color uses the Tailwind classes `text-strong`, `text-body`, `text-muted`, `text-accent` (mapped to those variables in `tailwind.config.js`), not Tailwind's `gray-*`/`white` palette.

All card types share one base in `styles.css` (`--surface` background, `--border` border). **Only interactive elements react to hover**: `.tech-card` (the only card that is a link) brightens and lifts; project/research/teaching/YouTube cards are static.

**Interaction rules:** every hover effect has a matching keyboard-focus effect — in Tailwind, pair `hover:x` with `focus-visible:x` (and `group-hover:` with `group-focus-visible:`); in `styles.css`, list `:hover, :focus-visible` together. Movement (lift, scale, smooth scroll) is gated on reduced-motion preferences — use `motion-safe:` in Tailwind or `@media (prefers-reduced-motion: no-preference)` in CSS. Color changes don't need gating.

**Accessibility conventions:** an image inside a link that already has a visible text label gets `alt=""` (tech tiles); icon-only links get an `aria-label` and a ≥44px hit area via `inline-flex p-3 -m-3` (looks the same, bigger target); decorative glyphs (▸, →) are drawn in CSS or wrapped in `aria-hidden="true"`; a card has one tab stop per destination (duplicate links get `tabindex="-1" aria-hidden="true"`); repeated link text like "Watch Series" gets an `sr-only` suffix naming its target. Styled `<ul>`s get `role="list"`, because Tailwind's reset strips list semantics in Safari. **Every text link with `target="_blank"`** gets the `ext-link` class (a CSS-drawn ↗ in the link's color) plus `<span class="sr-only"> (opens in new tab)</span>` inside it; icon-only links and tech tiles skip the ↗.

**Design choices to keep** (deliberate, not defaults): section titles are centered (the owner prefers the symmetry); "YouTube Series" is a small centered subheader; the first name in the h1 is solid `text-accent`; no glows, gradients, or emoji; pills are kept as abstract-style keywords on every card.

**Assets** (`assets/`) hold images referenced directly in `index.html`; favicons and the web manifest live in `assets/icons/`. The headshot is `assets/headshot.webp`, a 352px square (2× its largest 176px display size); keep photos at ~2× display size in WebP. Social and project-link icons are inline SVGs, not image files: 24-unit viewBox, `fill="currentColor"`, `aria-hidden="true"` (the link carries the `aria-label`), 32px in the hero and 20px on project cards. A glyph that doesn't fill its square (the YouTube play button) gets a cropped viewBox (`2 2 20 20`) so it matches its neighbours' visual size. Some tech logos and the YouTube thumbnails are loaded from external URLs (python.org, Wikimedia, GitHub, i.ytimg.com) rather than local files.
